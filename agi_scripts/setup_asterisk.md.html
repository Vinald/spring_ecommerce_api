**Getting your IVR Setup** This guide is essentially to help you get started with setting up MOTECH and Asterisk as well as setting up the python scripts as well as explain the use of some of the scripts included in this folder. Setting up Asterisk ============= Prerequisites: - A VM with Ubuntu 18 LTS (The server version is most preferable for its speed). The VM should be updated and preferably have the following packages: vsftpd, openssh-server. Follow the guide [here]("https://computingforgeeks.com/how-to-install-asterisk-16-lts-on-ubuntu-18-04-16-04-debian-9") to get Asterisk set up on your local machine. For the purposes of this setup, configure the following: In the /etc/asterisk/sip.conf file, add the following lines, save and exit: ``````` [ivrtest] type=friend context=phones allow=ulaw,alaw secret=12345678 host=dynamic `````` In this, your basically telling asterisk that i should recognise any peer that tries to authenticate with the user credentials: - Username : ivrtest - Password: 12345678 These are the credentials you would then configure on your SIP phone or soft phone. You are free to chage them though if you wish. In the /etc/asterisk/extensions.conf file, add the following lines, save and exit: ``````` [phones] exten => 100,1,NoOp(This is a Test IVR) same => n,Answer ; same => n,Saynumber(1) ; same => n,Playback(/home/asteriskuser/en/001_02_01_TAMAGreeting1Generic) ; same => n,MP3Player(/home/asteriskuser/en/001_02_01_TAMAGreeting1Generic.mp3) same => n,AGI(/home/asteriskuser/pyfiles/agi-test.agi) same => n,Hangup `````` This basically tells Asterisk that when any phone/peer that is connected to it Dials 100, then that Dialplan should be followed. Lines starting with ";" are commented out lines showing some basic Dialplan applications. Our focus shall be on the AGI and that is how it is referenced in Asterisk. Once you are doe with that, refresh Asterisk so tht it can pick up the new configs by entering the commands: ``````` asterisk -rvvv Asterisk 16.6.2, Copyright (C) 1999 - 2018, Digium, Inc. and others. You shall need a soft phone on which you can test some of your calls. For my testing, I used wxCommunicator which is a Windos softphone that can be found [here]("https://sourceforge.net/projects/wxcommunicator/"). When you download, install this application and open it, you shall be welcomed with a prompt that should be filled in like this: - Sip proxy : "the ip of your asterisk VM" - Line URI : "Can be left blank" - Username : "ivrtest" - Password: "12345678" Remember, this are the configurations we made in the **sip.conf** file. Aftr this, it should successfully register and should be able t make calls. However, for some reason that I wasnt able to figure out, it cant receive calls. For receiving calls, I'd typically use an actual SIP phone. For FTP, I use MobaXTerm that can be downloaded [here]("https://mobaxterm.mobatek.net/download.html"). In the Sessio tab, I use SFTP for my FTP. Make sure the credentials you use to login have the permission to read an write to the folder you want to write to. This shall come in handy for copying the audio files to the VM or copying the Motech Install Script. Getting MOTECH Installed ===================== Prerequisites: - A VM with Ubuntu 18 LTS (The server version is most preferable for its speed). The VM should be updated and preferably have the following packages: vsftpd, openssh-server. - The VM should have atleast 12GB space. Get access to the CFL install script and have it locally available on your new VM. The script can now be accessed under Projects, Your Projects, Norman - scripts. You can download or clone it from there. Navigate to the directory and install the script: ``````` cd cfl710/ ./install-cfl710.sh `````` This may take up to 30 minutes. Once this is done. Run the command below to start the MOTECH containers: ````` docker ps ````` You shall have to wait for atleast 8 minutes from the moment you run this command for the MOTECH database to be ready for use. Take note of the IP of your local machine. This is where the MOTECH database shall be accessed from. You can then access the vxml callflow files. Am example is: **"http://192.168.88.251/motech-platform-server/module/callflows/in/voxeo/flows/MainFlow.vxml?phone=256750046950"** The **192.168.88.251** would represent the local IP for your VM. To access the call flow for a particular number, add the **?phone=256750046950** infront of the **Mainflow.vxml**. The phone number added must be in the MOTECH database for the correct call flow to be generated. Otherwise the default call flow **"We_are_Sorry"** is what you shall be directed to. This nomenclature is what shall be used for options like **pin**, or **choice** when a user needs to choose an option in the IVR menu. For example, for pin, it would look like: **"http://192.168.88.251/motech-platform-server/module/callflows/in/voxeo/flows/MainFlow.vxml?pin=1234"** With this you should be able to interact with MOTECH successfully. Note that after the **Mainflow.vxml**, the following links are autogenerated by MOTECH and are always different because for each link clicked or downloaded, a database entry is made/updated. The only link that is typically constant is the first **Mainflow.vxml** link. The AGI Python scripts ====================== There are two main AGI Python scripts namely: agi-test.agi ------------- This file contains the helper functions needed to enable interaction with Asterisk through python. Also included are Demo functions to help with certain routine tasks. This file shall be updated with more functions as need arises or simply modified to add more specific helper functions. This file is designed to be **called** by the main AGI file that shall be in the **/etc/asterisk/extensions.conf** file. It wont feature in the Dialplan but for testing, I tested it directly in the Dialplan to make sure it was working right. It should be noted that any error in this file shall cause the whole file to crash and through the AGI wont work. So this file must be edited with caution. agi-main.agi ------------- This is the main python file that shall be present in the Asterisk Dialplan. ``````` [phones] exten => 100,1,NoOp(This is a Test IVR) same => n,Answer same => n,AGI(/home/asteriskuser/pyfiles/agi-main.agi) same => n,Hangup `````` **NOTE:** I pointed the AGI to the located of this file in my test environment i.e. **/home/asteriskuser/pyfiles/agi-main.agi**. This shall definitely be different in your case and shall probably be this IVR repo that you would have cloned. Its important that you specify the path especially for purposes of testing the implementation. In production, this files can be stored in the default Asterisk AGI repo found atleast **/var/lib/asterisk/agi-bin**. Also important to note, you shall need the audio files locally present on your VM. Get intouch with Conrad or Norman for this. There may be places where the audio files to be played are referenced to a local directory on your machine, or accessed online.
